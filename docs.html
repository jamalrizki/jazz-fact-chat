How it works

Tools, tool calls, chord charts, the reference search, and the MCP server behind Jaizz Chat.

The short version

Jaizz Chat is a chat app backed by a free open-weight model (gpt-oss-120b on Groq, with OpenRouter's free models as a fallback). On its own, the model will confidently make up who played on a record, misspell a chord, or write a chart from a half-remembered lead sheet. So it is given tools: small functions that fetch real data or do exact work in code.

  • Players and records: Wikipedia, MusicBrainz, and web search limited to jazz references (All About Jazz, Discogs, the Jazz Discography Project).
  • Chord charts: a library of over 2,000 tunes, shown as jazz charts, in any key.
  • Chord notes: every chord symbol is spelled by code, not by the model.
  • Theory and practice: a search over scoped reference material on jazz theory, harmony, arranging and history.

The model answers well-known things directly and looks up anything it isn't sure of. Most of the tools are also published as an MCP server, so any MCP client (Claude, an IDE, the MCP Inspector) can use them without this website.

What happens when you ask a question

  1. Browser → Worker Your question, plus the conversation so far, goes to a Cloudflare Worker. The API keys live there as secrets and never reach your browser.
  2. Worker ↔ MCP server The Worker acts as an MCP host. It runs initialize, then tools/list, to learn which tools exist and what arguments they take.
  3. Worker → model It sends the model your conversation and the tool definitions (names, descriptions, JSON Schemas). The model never sees the tool code.
  4. Model → Worker The model either answers directly, or replies with a tool call such as album_lineup({"album": "Kind of Blue", "artist": "Miles Davis"}). It cannot run anything itself.
  5. Worker → tool → model The Worker checks the arguments, runs the tool via MCP tools/call, and sends the result back to the model. Steps 4–5 repeat (at most 4 rounds) until the model answers in plain text. Limits are kept in code, not left to the model: at most 2 web searches and 2 reference searches per question.
  6. Worker → browser Before the answer goes out, code strips any "(Source: …)" or "(per Wikipedia)" tags the model added, because the page already shows what ran. You get the answer plus a trace of every tool call: expand "Used N tools" under any answer to see the exact arguments and raw results. A chord chart, if there is one, comes straight from the tool to the page.

When the model calls which tool

The model picks a tool by reading its description, so the descriptions are written as instructions. In practice:

  • "Who played on A Love Supreme?" → album_lineup. Any question about personnel or release year. The description says never to answer these from memory. Code picks the original pressing over deluxe or expanded reissues, whose bonus tracks credit players who weren't on the album.
  • "Who was Mary Lou Williams?" → lookup_musician. Biography, dates, instruments, career.
  • "How many albums did Miles Davis make with John Coltrane?" → search_jazz. The general fallback: it searches Wikipedia (plus All About Jazz, Discogs and the Jazz Discography Project) and returns only the passages relevant to the question. The model uses it whenever it isn't sure, and whenever another tool comes back empty.
  • "Chart for My Funny Valentine in F." → chord_chart. See Chord charts.
  • "What notes are in E7#11?" → chord_voicings. See Chord notes.
  • "Explain the Lydian Chromatic Concept." → search_theory_books. Theory, harmony, improvisation, voicings, arranging, practice and history. See Reference search.
  • "Tell me a fun jazz fact." → random_jazz_fact. Only for trivia requests, never to answer a specific question.
  • "What instrument did Charlie Parker play?" → no tool. Well-established facts are something the model knows well enough.

If a tool finds nothing, the model is instructed to say so instead of filling the gap from memory. Ask about an obscure record and you'll usually hear that the personnel isn't listed, rather than invented names. The chat also stays on jazz: questions about gear, repairs, health, legal or money matters get a one-line "that's outside what I cover".

Chord charts

Charts come from a library of over 2,000 tunes. They are drawn as charts, with sections, repeats and first and second endings. For a tune written with a D.C. or D.S. and a coda (or Fine), code also works out the form as you'd play it: back to the top or the sign, no repeats the second time, then the coda. That way the form and bar count the chat gives you include the whole trip.

  • Never from memory. If a tune isn't in the library, the chat says so and suggests close matches. A confident-looking wrong chart is worse than none.
  • Any key, transposed in code. Transposition is exact arithmetic that language models often get wrong, so the model only asks for the key.
  • Charts for horn players. Ask for "Blue Bossa for tenor" or "Autumn Leaves for alto" and the chart comes back in your written key: up a whole step for B♭ instruments (trumpet, tenor, soprano, clarinet), up a major sixth for E♭ (alto, bari), up a fifth for horn in F. The model only picks the instrument; code adds the interval, and the chart header says which instrument it's for. The reply gives the concert key too.
  • The chart skips the model. The tool sends the chart straight to the page as data; the model just adds a sentence or two about the key or form.
  • PDFs and setlists. Each chart has a ⋯ menu: download it as a PDF, or add it to a setlist. The Setlist button at the top lets you reorder the tunes and download them all as one PDF, with a cover page. "Print for" switches the whole set to concert, B♭, E♭ or F in one go: the page asks the chart tool again for each tune, so the same code does the transposing. The setlist is saved in your browser only.
  • The library itself isn't published. It ships with the Worker; the source code includes a 12-tune sample.

Chord notes, spelled in code

Language models get accidentals and intervals wrong surprisingly often. So every note name the chat gives you for a chord comes from chord_voicings, a small piece of code that reads chord symbols the way a musician does:

  • A chord symbol is read as degrees of the root's major scale: 7 is the lowered 7th, #11 the raised 4th, and so on. Triads, 6ths, 7ths, extensions, alterations, alt, add chords and slash chords all work.
  • Each note gets its letter first, then its sharp or flat, so spellings are correct, not just the right keys: E7#11 is E G♯ B D A♯, and G♯maj7 is G♯ B♯ D♯ F𝄪.
  • It also gives inversions and the rootless form, and, if asked, the usual chord-scale (Dorian for m7, Lydian dominant for 7#11, altered for 7alt, and so on).
  • It can check notes from elsewhere against a chord and its scale.
  • Give it just a root ("a rootless A chord") and it shows labelled examples instead of guessing the quality.

Reference search

For theory and practice questions, the chat searches scoped reference material covering harmony, chord-scale theory, improvisation, voicings, arranging and jazz history. This is retrieval-augmented generation (RAG):

  1. The reference material was split into short passages ahead of time, and each passage was turned into a list of numbers (an embedding) that captures its meaning.
  2. Your question gets the same treatment, and the 30 passages closest in meaning come back from a vector database.
  3. A second model (a reranker) scores how well each passage actually answers your question. Being close in meaning isn't the same as being relevant, so passages below a fixed score are dropped.
  4. The best three go to the chat model, which explains them in its own words. If none pass, it says it didn't find anything rather than improvising.

Answers explain the material in the chat's own words, and the search isn't offered on the public MCP server.

Honest limits

  • The model is free and open-weight. Tools make it far more accurate, but it can still misread a result or skip a tool call. Check the tool trace.
  • MusicBrainz is community-edited. Plenty of jazz records have no personnel credits there, and some listings include players from bonus tracks on a later reissue.
  • The reference search reads text, not notation. Ideas explained in words come through well; voicings printed only as music examples don't, which is why chord notes come from code instead.
  • Free tiers are rate-limited. Busy moments can mean a short wait; if Groq is busy, OpenRouter answers instead (the line under each answer shows which one did).
